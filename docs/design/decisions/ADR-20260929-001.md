# ADR-20260929-001 — 再試行の識別と保存順序

工程モデル | 工程日：2026-09-29 | 担当：全員

## Context

3人全員で設計案を比較した検討例。現在の採用構成との対応を確認する。

## Problem

再試行の識別と保存順序を、限られた作業枠で選ぶ。

## Options

clientId一意制約 + 部屋行FOR NO KEY UPDATE／時刻順のみ、クライアントだけで重複除去

## Trade-offs

ID採番順とコミット順がずれるとafterで未確定の低IDを飛ばす。採番前に部屋単位で直列化する。

## Decision

clientId一意制約 + 部屋行FOR NO KEY UPDATE

## Reason

ID採番順とコミット順がずれるとafterで未確定の低IDを飛ばす。採番前に部屋単位で直列化する。

## Consequences

同室送信は待機する。別室は独立。表示カーソルの問題は翌日のクライアント検証で調べる。

## Risks

同室送信は待機する。別室は独立。表示カーソルの問題は翌日のクライアント検証で調べる。
